# 近期修复与可选站点适配

## 浏览器与会话

- 同一持久化浏览器 profile 不再并发启动；关闭和取消时保留占用锁直到清理完成，不删除仍被使用或无法确认归属的 Chromium 锁。
- 手动粘贴 Cookie 导入与签到共享账号占用，避免凭据互相覆盖；导入阶段、验证阶段设超时，失败时保留可恢复的 IdP Cookie，错误信息不带 URL 查询参数或凭据。
- 保留手动 Cookie 导入，不提供浏览器扩展自动导入入口。

## 调度与协议

- `checkin_after` 只表示本地时间今天最早可以尝试的时刻；是否已经签到按本地自然日及站点记录判断，避免凌晨抢跑。
- New API 分支登录响应中的 Bearer token 会用于后续请求。
- 自定义后端更新了网络超时，并优先读取与站点域匹配的登录 Cookie，避免复用过期会话。

## 可选的 open-only visit 适配

某些站点在已登录页面加载时，由站点自己的 SPA 轮换 refresh token 并发放每日额度。对于这种实现，可使用专用 open-only 分支：只打开已有会话页面，不主动重新 OAuth 登录，不主动 POST 签到或手工刷新 token；读取站点 `type=1` 的 `Daily allowance` 流水确认到账，并保留最新 refresh cookie。打开页面或读到余额本身不等于当天签到成功。

此适配**默认关闭**，且只对账号机制选为 `visit`（打开页面即签到）的配置主机生效。部署时将环境变量传入面板进程或容器，例如：

```yaml
environment:
  CHECKIN_OPEN_ONLY_HOSTS: "relay16.example,relay17.example"
```

`relay16.example` 等均为匿名演示域名，不是真实服务。请替换为你实际使用、且具有上述 SPA/流水行为的站点主机名。值为逗号分隔的主机名列表，不带协议、路径或端口；忽略大小写、首尾空格及末尾点，仅精确匹配，不自动匹配子域。未设置或空字符串不启用任何主机。不要仅为绕过失败而启用此适配，不同站点的流水协议可能不兼容。

首次使用须通过保留的手动登录或 Cookie 导入建立站点会话；若页面已退出登录，需要先恢复会话。未确认当天到账时返回失败并允许稍后重试，但仍保存本次轮换的有效凭据。

所有测试使用匿名 fixture 和模拟浏览器/HTTP，不需真实站点凭据；发布源码不包含生产配置、内部地址或账号信息。上游 MIT 许可证保持不变。
